# AI 协作裁决（E 原语）：比"用了什么工具"重要一百倍

> 里程碑提交里除了项目相关数据，**必须有 AI 使用相关数据**，而且权重更高。
> 但记录的不是工具日志，是**人机协作里的判断**。

## 1. 一条字段，五个子项

用一个 `group_list` 收全部，子字段只能是 `text` / `textarea`：

```jsonc
{
  "key": "ai_collab",
  "title": "AI 协作裁决",
  "type": "group_list",
  "required": true,
  "min_items": 1,
  "max_items": 2,
  "layout": "cards",
  "guidance": "记的是你的判断，不是工具日志。工具名、次数、时长不算数据。",
  "fields": [
    { "key": "intent",     "title": "我向 AI 要什么，为什么（原动力）", "type": "textarea", "required": true },
    { "key": "options",    "title": "AI 给出几个方案／几条路（各自要点）", "type": "textarea", "required": true },
    { "key": "choice",     "title": "我选了哪个、为什么、放弃了哪个", "type": "textarea", "required": true },
    { "key": "prediction", "title": "我预期它会在哪对、在哪会错", "type": "textarea", "required": true },
    { "key": "verify",     "title": "我怎么验的（问真人／查数据／实测／找反例）+ 结果", "type": "textarea", "required": true }
  ]
}
```

## 2. 为什么是这五项

| 子项 | 逼出的能力 | 缺了会怎样 |
|---|---|---|
| `intent` | 说清自己到底要什么 | 变成"我让 AI 帮我做设计"这种废话 |
| `options` | 让 AI 给空间，而不是给答案 | 只有一个答案，没有比较 |
| `choice` | 在人机分歧处做裁决 | 判断外包给 AI |
| `prediction` | 对 AI 输出的预判 | 无法暴露"AI 哪句是幻觉" |
| `verify` | 把 AI 输出拉回现实 | 停留在"AI 说得挺对" |

**这五项合起来，就是"用 AI 做项目"的能力本身**——注意 E 的 `prediction` 与 C 原语的 `prediction` 是两件事：E 预判「AI 会在哪里错」，C 预判「现实会发生什么」，两处都填、不许合并。

## 3. 三条红线

1. **不做工具日志**：工具名、调用次数、用时、截图，统统不是数据。
2. **`choice` 必须有自己的理由与放弃项**：只写"我觉得 B 更好"不算。
3. **`verify` 必须有外部锚**：问真人、查数据、实测、找反例——不能是"我又问了一遍 AI"。

## 4. 每关怎么配

| 关类型 | 项目原语 | AI 协作 | 交付字段 |
|---|---|---|---|
| 立项 / 调研 | A 或 B | **E（必选）** | 1 个 |
| 方案 / 决策 | A 或 C | **E（必选）** | 1 个 |
| 落地 / 成本 | C 或 D | **E（必选）** | 1 个 |
| 交付 | D | **E（必选）** | 1 个 |

**E 每关都在**——"结合 AI 做落地项目"是这门课的主体，不是附加项。

### 4.1 减负机制（v4.1，解决"每关五项 = +20 行"）

| 关的类型 | E 要填几项 |
|---|---|
| 有 AI 参与的关键关 | **五项齐备** |
| 其余关（轻量 E） | 至少 `intent` / `options` / `choice` 三项，`verify` 可留空 |
| 每门课的下限 | **至少两关五项齐备**（其中一关必须含带外部锚的 `verify`） |

轻量关的 `verify` 留空不算缺证据，但**不得写"又问了一遍 AI"**。

### 4.2 `verify` 的三档外部锚

| 档 | 长什么样 | 什么时候允许 |
|---|---|---|
| 弱锚 | 问了一个真人、查了一份公开资料 | 立项/早期关，须标注「弱锚」 |
| 单锚 | 一次实测/一次询价/一条可核对的原始记录 | 中段关 |
| 交叉锚 | 两个独立来源互相印证，或预测被现实验证/推翻 | 落地关与交付关 |

`intent` 一类写法（"我让 AI 帮我做设计"）视为未填。

## 5. 评价怎么挂

每关至少一个维度 `ai_collaboration_quality`，权重 **0.2–0.3**，档位只描述证据形态：

| 档 | 证据形态（写这个，不写"优秀/良好"） |
|---|---|
| 1 | 只写了工具名或"用了 AI" |
| 2 | 有 `intent` 与 `options`，但 `choice` 无放弃项 |
| 3 | 五项齐备，`verify` 有外部锚 |
| 4 | 在 3 之上，`prediction` 被现实验证或推翻，且写明修正 |

## 6. 与"不判质量"的关系

- AI 评审给出的维度等级是**给导师的草稿**，导师改完才算数；学员看到的等级必须是导师确认后的。
- 档位描述只写"有没有这类证据"，不写"好不好"。
- `core_comment_prompt` 里写清：先摘要，再指缺口，不替导师定级。

不要粘贴整段对话。用平台公共笔记里的整理模板：
- 主笔记：`assets/public-notes/ai-record-to-fields.md`
- 按任务类型的变体：`assets/public-notes/task-type-variants.md`
- 课程可在里程碑 `resources` 里挂对应的那一份；
- 写 `intent` / `options` 前可查外部术语卡片库（`assets/public-notes/ai-terms-cards.md`），把模糊说法换成说清楚的说法。
