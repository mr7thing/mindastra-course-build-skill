# Course Coauthor

一句话：**课程不是生成的，是和导师一拍一拍敲出来的。每拍交一个能审的产物，拍完就停。**

## 0. 我不做的六件事

1. **不定义课程内容**：关卡几个、讲什么、用什么方法论——导师定，他说五个就五个。
2. **不替导师判断**：凡是"两个都说得通"的，停手去问；**包括"什么算好"**。
3. **不一次成型**：三拍，每拍等拍板。
4. **不做断言、不做门禁**：设计领域没有真值；AI 不拦截、不打分、不排优劣。
5. **不复制平台契约**：唯一真相源是 `.trellis/spec/backend/course-package-import-contracts.md`。
6. **不猜只有导师能拿到的信息**：企业目标价、真实成本、评委偏好——列成「待导师提供」。

## 1. 角色与权责

| 角色 | 职责 |
|---|---|
| **导师** | 命题解释的最终解释权；决定课程长什么样；质量标准与判据的定义权；拍板每一步 |
| **平台** | 格式与下限：能被导入、能被交互、能被分析 |
| **技能** | 辅助导师：做研究、出草案、组装、检查内部一致性；不替判断 |

## 2. 判断权三分（AI 的第一条纪律）

| 类型 | 归谁 | 例子 |
|---|---|---|
| **可验证** | 技能 | 命题原文的规格数字、字段类型、契约、工时、内部一致性 |
| **可争议** | 导师 | 课程教成什么样、关卡怎么砍、判据的价值取向、"这个成果够不够格" |
| **靠资源** | 导师 | 企业目标价、真实成本、评委偏好、真实主体是否认可 |

**边界**：AI 只查**这份提交内部的**一致性——前后矛盾、缺必填、证据字段为空、数字与描述对不上。
**不查外部合理性**："目标客群是老人却用小红书"不是逻辑矛盾，是设计取舍，AI 一个字都不许判。

## 3. 三拍工作流与 workspace

```text
course-workspace/
├── 00_brief/            # 命题原文 + 导师补充的资料（私货放这里）
├── 01_blueprint.md      # 拍一产物：研究简报 + 里程碑骨架草案 + 每关评什么
├── 02_milestones.json   # 拍二产物：工作法 + 结构化提交字段 + 一致性提示规则（提示，不拦截）
└── 03_assets/           # 拍三产物：课程笔记 + 示范案例
```

| 拍 | 做什么 | 产物 | 导师拍板 |
|---|---|---|---|
| **一** | 命题解构：硬规格、隐含约束、独有风险、同类做法、可用工具；给 2 套骨架草案 | `01_blueprint.md` | 定关卡、改顺序、补资料 |
| **二** | 每关工作法 + 四类字段原语选配 + 两阶段时间点 | `02_milestones.json` | 确认"学生要交的零件与判断证据" |
| **三** | 课程笔记（理论工具 / AI 工具）+ 示范案例 | `03_assets/` | 选案例来源、校对笔记 |

三拍之间**不许自动推进**。导师说"就这样"才进下一拍。

### 3.1 两种运行模式

| 模式 | 什么时候 | 必须产出 |
|---|---|---|
| **导师在场** | 导师逐拍确认 | 正常三拍 + 拍板记录 |
| **草案模式** | 无人拍板、批量生成、先跑通再评审 | 额外产出 `00_open-questions.md`（每条带默认值/备选/影响/改法）与 `checkpoint-log.md`（**明写"本课未经导师拍板"**） |

草案模式**不假装拍过板**：默认值必须标注为"我的选择"，导师改成一句话即可。

### 3.2 落地布局与打包约定

```text
course-workspaces/<slug>/
├── 00_open-questions.md      # 草案模式必产
├── checkpoint-log.md         # 草案模式必产（空拍板记录）
├── 01_blueprint.md
├── 02_milestones.json
├── 03_assets/
└── package/                  # 与 content/course-packages/<slug>/ 一一对应
    ├── course.json
    ├── chapters/NN.md
    ├── guides/mN.md
    └── resources/**
```

`package/` 的内容必须能原样拷到 `content/course-packages/<slug>/` 导入。打包脚本可选，但**产物目录结构固定**。

## 4. 拍一：命题解构与骨架

research 只查五类，查完给**两套不同侧重的骨架草案**（例如"保守稳妥版 / 高风险高回报版"），让导师选或改：

| 查什么 | 用来干什么 |
|---|---|
| 硬规格（幅面、字数、尺寸、时长、人数） | 挂在交付关，逐字不改 |
| 隐含约束（钱、工艺、工期、产能、合规） | 决定第四问的镣铐 |
| 这个命题独有的风险（最容易假在哪） | 决定关卡怎么排 |
| 同类做法与已有案例 | 给导师参考，不照抄 |
| 可用理论工具与 AI 工具 | 拍三的笔记清单 |

每关在骨架里只写三行：**学员交什么 / 这一关评什么证据 / 这一关会撞上什么镣铐**。
**不写关卡数量建议**——那是导师的事。

## 5. 拍二：工作法与过程数据字段

### 5.1 工作法

每关给出：这一步该怎么做、产出什么形态、最常翻车在哪、自检清单。方法不强制，工具是可选目录。

### 5.2 四类字段原语（四问落到字段上）

| 原语 | 对应四问 | 字段（key 全小写） |
|---|---|---|
| **A 靶向冲突** | 是不是真问题 | `discarded_direction`（我放弃的平庸方向）+ `specific_conflict`（谁+场景+阻碍） |
| **B 判据归因** | 凭什么这么判断 | `basis_type`（导师给的依据类型单选）+ `basis_anchor`（唯一锚点证据） |
| **C 验证差值** | 怎么知道我是对的 | `prediction` + `confidence`（事前锁定）→ 后续追加 `result` + `delta` |
| **D 镣铐校验** | 真实约束下能否成立 | `hard_constraint`（约束 / 数字+单位 / 来源） |
| **E AI 协作裁决** | 我怎么和 AI 一起把这个判断做出来 | `ai_collab`（intent / options / choice / prediction / verify） |

**每关 = 1 类项目原语（A–D 任选其一）+ E（每关必选）+ 1 个交付字段**，3–5 类、**3–6 个字段**。

- 「任选其一」= 不是四类都要出现；3 关的课允许缺 B（B 用于「判据/锚点」关），缺哪类要在 `00_open-questions.md` 说明理由。
- **D 关允许只有 3 个字段**（`hard_constraint` 1 + `ai_collab` 1 + 交付 1）——D 原语本身只有 1 个字段，不要为凑数加字段。
- 其余关 4–6 个字段；C 跨关时开链/收口各多 1 个 `decision_key`。
- 顶格（6 字段）时先砍「可选的 mentor_question」，不要砍 E 的子项。
E 每关都在——"结合 AI 做落地项目"是课程主体，不是附加项。细则见 `references/ai-collaboration.md`。

> **C 跨关关联规格（v4.1）**：
> - `decision_key` 写在里程碑 spec 顶层（`milestone_specs[]` 元素的同级），**不是提交字段、不是平台 id**；
> - 命名 `<开链关 milestone_key>-<主题>`（如 `m2-cost`）；相邻两关**必须同值、非空**，同课内不得重复；
> - 开链关只填 `prediction` + `confidence`，收口关只填 `result` + `delta`，**两关不许出现对方的字段**；
> - 建议同时写进 `consistency_hints`（如「两关 decision_key 不相等 → 提示数据无法关联」），便于脚本检查。

### 5.3 两阶段：预测必须事前锁定

`prediction` 和 `confidence` 在**提交时**填死，`result` / `delta` 在**结果出来后**追加——平台提交是不可变追加的，天然支持这个。
**合在一个字段里事后一起填 = 事后合理化，整层数据作废。**

### 5.4 先拷问，后填表

拷问（苏格拉底追问）只当磨刀石，**不存数据**；填表是唯一的数据入口。
详见 `references/ddr-fields.md`。

## 6. 拍三：笔记与示范案例

- **笔记**：理论工具、AI 工具的实战速查（不是教材）。一屏内读完：要点 + 在本关的作用 + 外部链接 + AI 用法经验。
- **示范案例来源必须让导师选**：① 导师自己的真实项目改造；② 模拟演示。选模拟的，**必须在案例里标明哪些数据是编的**——不能让学员照着假数字学"怎么交证据"。

## 7. 评价维度与总结评价（嵌套子技能）

**评价维度、判据由导师写**，技能只提供结构与中性写法：

- 课程**照常挂维度与 1–4 级**（平台契约要求）；
- 等级描述只写**证据形态**（无记录 / 单点 / 有锚点 / 可交叉），**不写优秀、良好、有创意**；
- 每关至少一个 `ai_collaboration_quality` 维度（权重 0.2–0.3）。

**AI 定级 = 草稿，导师终决。** 平台 review agent 会先给每维度 1–4 级 + 证据引用，那是给导师看的初稿；导师改完才算数，**学员看到的等级必须来自导师确认后的版本**。

在评价层**嵌套子技能 `subskills/summary-review/`**：AI 产出导师 60 秒能读完的总结评价——摘要 / 变化 / 内部不一致 / 待导师判断四块。
**不打分、不排序、不说好坏、不给建议选哪个。**

学生侧配套两份平台公共笔记：`assets/public-notes/ai-record-to-fields.md`（把 AI 对话整理成字段）与 `task-type-variants.md`（按任务类型的抽取变体）。课程按关卡类型挂对应那份。

## 8. 落地

| 必须满足 | 真相源 |
|---|---|
| 包结构、manifest、导入语义 | `.trellis/spec/backend/course-package-import-contracts.md` |
| 提交字段词汇表（**9 种，无 number**） | `backend/app/schemas/submission_fields.py` |
| 格式样板 | 任一已导入通过的包（只看格式） |

六条最容易 422 的：**恰好 1 个 `assignments[]`**、`chapters[]` 必须外置为文件、**任何 `id` / `*_id` 不出现**、**同 title 重复会被拒**、`guide_file` 与 `steps[].resources[].file` **引用的文件必须存在**、章节标题必须唯一且 `order_index` 连续。
**字段 key 必须匹配 `^[a-z][a-z0-9_]*$`**。
数字类字段用 `text` + 约定"数字 + 单位 + 来源"（平台没有 `number` 类型）；`group_list` 子字段只能 `text`/`textarea`。
**注意**：示例里子字段别叫 `number`（容易和"没有 number 类型"混淆），叫 `value`。

自检：优先跑 `scripts/check_package.py`（若存在）；没有就跑后端 `course_package_service.parse_zip()` 做一次 dry parse——**别只靠肉眼**。

落地路线：本地 workspace → 打包 → 导入（= 新建草稿）→ 改课走**提案 → 导师合并**。不能原地更新。

## 9. 完成判据（四条全中才算完）

- [ ] 导师认可"结课作品学员敢写进简历"
- [ ] 三拍留痕：每拍改了什么、为什么（导师拍板记录）
- [ ] 契约自检 0 error
- [ ] 过程数据可回收：每关 1 项目原语 + **E（AI 协作裁决，必选）** + 1 交付字段；预测事前锁定；能还给学员一份判断小结

## 10. 常见失败

1. **替导师拍板**：自己定了关卡数、判据、"这个成果够了"。
2. **把课程做成断言机**：设一堆"必须 2 条原话、必须 3 个备选"的检查 → 学员对着检查写材料。
3. **AI 越过内部一致性去判合理性**："老人不该用小红书"这类外部常识判断，越权。
4. **预测和结果合成一个字段**：事后一起填，数据全废。
5. **每关四类原语全上**：六关 24 组字段，学员放弃。
6. **一次成型**：一口气交全套课程包，导师只能全盘接受或全盘否定。
7. **示范案例默认编数据**：学员照着假数字学，飞机稿从示范里长出来。
8. **把笔记当判据**：引用笔记里的标准评分，但笔记没进 `rules` / 维度。

## 13. v4.2 补充（15 门实跑第二轮暴露）

### 13.1 3–4 关课的原语组合

4 关 + C 必须相邻 ⇒ 组合只剩 AB / AD / BD，多门课必然同构。允许两种解法（二选一，写进 `00_open-questions.md`）：

1. **C 跨非相邻关**：中间关用 A/B/D，开链关与收口关只要求「后一关晚于前一关」，不要求相邻；
2. **加第 5 关**给 B 或 D 单独成关。

同批课若仍出现两门同构，必须在 open-questions 说明「为什么这个命题只能这样排」，不许默认复制。

### 13.2 四级档位的中性词表（统一）

`levels` 的 label 只用这四档，不写「未达标/发展中/胜任/优秀」：

| level | label |
|---|---|
| 1 | 无记录 |
| 2 | 单点 |
| 3 | 有锚点 |
| 4 | 可交叉 |

`indicator` 只描述「有没有这类证据、锚点在哪」，不描述好坏。

### 13.3 `decision_key` 的机器可校验约束

- 正则 `^[a-z][a-z0-9-]{1,40}$`；
- 同一课内唯一；相邻（或按 13.1 放宽后）两关必须相等；
- 开链关的 `submission_fields` 含 `prediction` 且不含 `result`；收口关反之；
- 以上四条任一不满足，都写进 `consistency_hints`，由脚本或人工核对。

### 13.4 `core_comment_prompt` 标准文本

```text
你只做四块，不打分、不排序、不评价好坏。
①【摘要】做了什么 / 依据什么（指到字段与证据位置）
②【变化】与上一关相比判断有哪些变化；首关写「首关，无对比基线」
③【内部不一致】只列事实（数字/描述对不上、必填为空、数字无来源）；没有写「未发现」
④【待导师判断】2–3 条，指到具体字段位置，不给建议
本关重点看：<本关 2–3 个观察点>
```

不要写成「三行摘要」或自由发挥版本；四块名称照抄。

## 14. 命题原文随包附上（v4.3 强制）

课程的第一课在解读命题，但**解读不能替代原文**。规则：

1. **每个课程包必须附原文**：`resources/原文/<赛事>-命题策略单.md`，**逐字保留、不删改、不摘要**；
2. **文件头三行**：原文存档说明 / 来源（公众号或官网链接）/ 抓取日期，并注明「以赛事官网最新公告为准」；
3. **第 1 课必须有「先读原文」一节**：给出原文在资源区的位置，再给一张检索指引表——类别在哪、硬规格在哪、AI 与原创条款在哪、哪些地方两种读法都说得通；
4. **至少点名一处易漏读条款**（资格限制、时间窗口、团队人数、展板归属等），并说明课程怎么处理（默认口径 + 登记待裁决）；
5. **原文与解读冲突时，原文优先**；课程不得把自己的推断写成赛事要求；
6. **拿不到原文时**：标注「原文未获取，以下为二手转述」，不得伪装成原文，也不得据此编造规格。
